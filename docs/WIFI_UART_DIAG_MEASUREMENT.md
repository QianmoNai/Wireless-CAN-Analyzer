## 方法和比较边界

真实 CH340 → UART 115200/8N1 → ESP32 → TLS → 现有 Linux 桌面 Channel / Qt 接收路径。120 B 随机数据分块，独立供给线程；8 KB/s 指 8,000 B/s，最大连续供给受 UART 线速限制。通过原有认证读取 P0，使用已有信任，不配网、不访问密码文件。每档计划 60 秒，失败即停止供给、关闭唯一串口，再独立认证读取保留计数。不人为断网。

旧基线设备地址为 10.42.0.226，路由经 enp3s0；本次烧录后该地址不可达，UDP 发现同一 ID 位于 192.168.1.221，证书固定校验及认证通过，走现有 wlan0。没有改变电脑网络或保存新的连接设置。**路径和观测开销均不同，不能把差异单独归因于 NODELAY。** 旧基线未独立核验已烧固件哈希。

UART ring 采样峰值第一次120 B，第二次升至240 B，第三次仍240 B；不是 ISR/FIFO 的精确峰值。最大供给和复现分别有108 / 35 B“主机接受−设备读取”差额，尚不能定位，不能用它们冒充已测得的 FIFO 溢出字节数。第三次 LAN 比 Qt 多1464 B；桌面断开会清空 packets/controls/deliveries，这是可疑边界，现有桌面 overflow 计数为0不能排除断开清理损失。原始接收均是输入前缀，序号缺口为0也不能发现末尾缺失。

Wi-Fi 断连数始终为1，reason=202 的事件发生于启动后261 ms、负载测试之前，不能将它当作测试断连原因。每次重新认证可读同一 boot_id 的计数，未见重启。内核发送缓冲高水位、精确 ring 丢字节、无线实际速率和重传次数仍 unavailable。

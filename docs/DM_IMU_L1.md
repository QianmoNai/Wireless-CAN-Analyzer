# 达妙 DM-IMU-L1 CAN 监控（App / ESP32 固件 1.17.0）

## 使用

1. 安装 android/dist/CAN-Scope-debug.apk，并更新配套 ESP32-S3 固件。
2. 用达妙上位机将 IMU 设置为 CAN 通信、主动上报。CAN 速率与总线一致（本项目默认 1 Mbit/s）。记录实际 CAN_ID 和 MST_ID。
3. 通道 → 电机与 IMU 配置 → 添加电机 / IMU → 达妙 → DM-IMU-L1。
4. IMU CAN_ID 填模块实际编号，返回帧 ID 填 MST_ID，均为十六进制。输入框初值只是占位建议，不表示模块出厂配置。同一总线每台 IMU 的 MST_ID 必须独立，且不能与电机反馈重叠。
5. 首页查看在线状态；点击卡片进入详情，查看姿态角、加速度、角速度、四元数、温度及采样 CAN 数据流。曲线可点击横屏放大，首页支持长按拖动排序、左滑删除和右滑配置。

本版本接收主动上报，不发送 IMU 参数修改、校准、置零或请求指令。IMU 供电请按模块手册使用，不要把 SN65HVD230 的 3.3V 供电要求套到 IMU。ESP32、收发器、IMU 通信地应可靠连接；沿用正确的 CAN 终端配置。

## 数据和频率

四类标准数据帧均使用 MST_ID、DLC8。首字节 1/2/3/4 分别为加速度、角速度、欧拉角、四元数；寄存器应答 0xCC 不计在线或进入曲线。

解码依据手册数据表及映射表：三轴加速度 ±235.2 m/s²，角速度 ±34.88 rad/s；Pitch ±90°，Yaw/Roll ±180°。16 位字段为小端无符号线性映射。四元数采用帧布局表的连续四个 14 位字段，各映射到 [-1,1]，不归一化掩盖原始误差。温度采用加速度帧第二字节。

上报限频是 ESP32→App 的采样上限，不更改 IMU 自身输出频率。四类帧各分配上限的 1/4，默认总计 100 帧/秒，即每类最多 25 帧/秒；未开启的类型不占用其他类型份额。刚订阅时各类可立即输出首帧。首页仅发送在线位图，单设备详情不传其他通道状态。原始数据流为采样后的帧，不保证总线逐帧无损。

每类数据独立刷新；曲线只加入对应帧的新参数，不把上一类值伪装成新样本。数值超过 2 秒未更新显示 —，总设备在线只表示近期收到至少一种合法帧，不代表四种数据齐全。

## 协议依据与不一致处

用户指定手册：[DM-IMU-L1 V1.2](https://github.com/THOK1224/Robot_Car/blob/main/doc/%E8%BE%BE%E5%A6%99BMI088/%E8%BE%BE%E5%A6%99%E7%A7%91%E6%8A%80DM-IMU-L1%E5%85%AD%E8%BD%B4IMU%E6%A8%A1%E5%9D%97%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E%E4%B9%A6V1.2.pdf)。下载文件 SHA256：519cb85126a857e6dae1bc9d3ec7ab32831aeeb1dd43260bf83be9b2a64d2b3c。

手册正文使用 CAN_ID/DLC8 寄存器请求；附录仍给出 0x6FF/DLC4 的另一种请求，因此暂不实现请求模式。四元数 W 在数据表占 byte1 和 byte2 高六位，附录示例掩码 0xF8 却漏掉 byte2 bit2；本实现按数据表保留该位，有独立边界测试覆盖。

协议扩展：订阅 family=2 表示 IMU；设备 event15 byte2 bit0 表示支持。旧固件不会被当成支持 IMU。IMU ID 不套用达妙电机低四位匹配规则。原有电机查询协议不变。

## 验证范围

通过解码极值、小端顺序、四元数打包位边界、非法帧/地址过滤、配置冲突及备份恢复、四类公平限频、首页过期、详情分组曲线/过期/数据流测试；大疆/达妙电机监控及固件主循环回归通过。ESP32-S3 和安卓 APK 构建成功。上述为 1.17.0 功能加入时的主机验证范围；当前 1.19.0 已验证烧录、启动及 CAN 接收，但不据此宣称完整 IMU 参数标定或所有 Android 手机均已实测。

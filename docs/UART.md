# 无线串口 · 固件 1.23.0 / App 1.21.0

本功能用于外部单片机 ↔ ESP32-S3 ↔ 蓝牙或局域网 Wi-Fi ↔ App 的双向字节传输。原 CAN 通信保留，在设备屏幕选择 CAN 或 UART，同一时刻只转发一种数据。Android 与桌面端共用串口页面。

## 接线

| ESP32-S3 开发板丝印 | GPIO | 连接外部单片机 |
|---|---|---|
| TX | 43 | RX |
| RX | 44 | TX |
| GND | GND | GND |

使用 **3.3V TTL**，不是 RS232/RS485，也不能直接接 5V 串口。代码将 UART1 映射到开发板通常标为 U0TXD/U0RXD 的引脚；若板卡厂商重新定义了 TX/RX 丝印，以该板原理图为准。固件 1.24.0 起关闭应用日志和控制台，原生 USB 用于 USB直连，应用 UART 数据流不混入日志。芯片上电 ROM 阶段仍可能在 TX 引脚输出启动信息，外部单片机应等待启动完成或用自己的帧头同步；没有修改 eFuse。

## 操作

1. 更新 ESP32-S3 固件和 Android App。原蓝牙连接或 Wi-Fi 安全配网方式不变。
2. 设备屏幕进入设置，选中“数据选择”，短按中键切到 UART。
3. 设置“串口波特率”，与外部单片机一致。支持 9600/19200/38400/57600/115200/230400/460800/921600，默认 115200；固定 8 数据位、无校验、1 停止位，无硬件流控。
4. App 收到设备状态后自动打开“UART 串口”。可按 HEX 或 UTF-8 文本显示接收内容，暂停显示、清空；可发送 HEX 或文本，并追加 LF/CRLF。
5. 切回 CAN 后恢复原 CAN 页面和功能；查询任务需要重新开启。数据类型和波特率断电保存。

### VOFA+ 波形

UART 页面内置轻量波形显示，Android 与桌面端使用同一套解析器。选择“自动检测”时会按输入特征识别协议；需要固定格式或避免二进制误判时，直接选择协议和通道数。

- **FireWater 文本**：每行一个采样点，通道值用逗号、分号、空格或制表符分隔，例如 `1.25,-2.0,0.5\n`。选择“自动（FireWater）”通道数时，每行的数值个数决定通道数。
- **JustFloat 二进制**：每个通道是 little-endian IEEE-754 `float32`，帧尾为 `00 00 80 7F`。JustFloat 没有通道数元数据，因此必须在页面选择发送端的通道数；默认 4 通道。

解析支持跨 BLE/Wi-Fi/USB 分包和帧边界，页面保留最近 4096 个采样点，显示点数可选 256/512/1024/2048，并显示最近窗口的实际采样率。波形暂停只冻结绘制，数据仍按有界缓存解析；清空、切换协议或 UART/CAN 模式会清除解析状态。波形显示是本机可视化，不会改变串口字节转发，也不提供外部设备执行成功的确认。

固件 1.24.2 也可通过既有 BLE / Wi-Fi / USB 的 `0x19` 设置命令查询或修改数据选择及上述 8 档波特率；type22 按 token 确认 NVS 保存结果，type21 继续报告串口选择、驱动状态和速率。无需按实体键进入 USB + UART 的命令示例见 [USB.md](USB.md#无需实体按键的远程设置固件-1242)，字段及拒绝规则见 [PROTOCOL.md](PROTOCOL.md#persistent-remote-settings-firmware-1242)。改波特率时会清理尚未发送的数据，应等待新 type21 就绪后再发送。

屏幕 UART 总览 RX/TX 单位是字节/秒，“丢弃”显示软件能统计到的丢弃字节；App 另显示 RX 序号间隙检测到的缺包数。CAN 模式仍使用帧/秒。选择 UART 后停止 CAN 查询与转发，但 CAN 控制器仍可能对总线上有效帧进行 ACK。

声音已合并为 **关闭 → 低 → 中 → 高**，中键直接切换，原独立音量项移除。升级保留旧声音与音量设置。

## 传输边界

- UART 是字节流，无报文边界；无线分包不会代表外部单片机的完整报文。二进制含 00/FF 可以透传。
- App 每次最多发送 4096 字节，分成 12 字节一段逐段等待确认。确认表示 ESP32 的串口输出完成，不代表外部单片机已接收或执行。
- 断线、切换数据类型/波特率时清理未发送的队列。已经进入硬件 FIFO 的字节可能继续输出；超时显示结果未知，不自动重发，防止重复执行单片机指令。
- 115200 是本地 UART 线速，不能保证蓝牙/Wi-Fi持续达到这个有效吞吐量。高波特率连续数据可能超过无线链路和界面能力；需要可靠传输时由外部设备协议提供帧长、校验、序号、应答及限速。
- 串口 RX 驱动缓冲 4096 字节；App 显示保留最近 64 KiB，暂停只暂停显示。队列溢出会丢弃数据。设备丢弃计数不包含所有无线空口损失；App 缺包检测也无法发现最后一个丢失包，不能作为无丢包保证。
- 双机 A/B 模式也支持 UART 字节转发，双方均需更新到支持 UART 的固件并选择 UART。配对方式沿用原屏幕配对，双机模式不连接 App。不同数据类型的包不会互相解释成 CAN/UART 数据。

## 丢弃统计口径

`type21.dropped` 和屏幕 UART 丢弃值以**有效载荷字节**累计，包含 UART worker 的首跳拒收、断线/改配置时待处理数据清理，以及下游 USB/BLE/LAN 最终拒收。USB/LAN 队列受理失败由上游计一次；已经受理后因会话失效、队列清理或输出失败而丢弃，由当前持有数据的下游计一次。USB 的部分 CUSB 帧不能通过校验，按该帧全部 UART payload 计；LAN TLS batch 只统计尚未完整写出的 20 字节帧（包括最后一个部分帧）的 UART payload，完整写出的帧不重复计。

丢失 `type20` 确认本身不计 UART 字节丢弃，因为物理串口输出可能已经完成。`type21`/设置/其他控制包也不计入 UART payload。计数在本次设备启动期间累计，BYE、重连、切换模式或波特率、读取状态均不清零；只有设备重启归零，32 位计数按模 2³² 回绕。`type21` 汇总本地 UART 累计值与双机链路的 UART 专用累计值各一次；测量每段负载应在排空后取前后差值，不能把多个累计快照相加。

这是设备软件可观察到的丢弃量，不能检测 UART FIFO 在错误发生前已丢失且无法读出的字节，也不能证明 BLE 空口、USB主机、TLS对端应用或桌面 UI 已收到。严格无损判断仍需外部输入/输出字节、hash 和 RX 序号共同核对。

## 验证范围

### 双机 B 软件回环（仅测试）

`CAN_DUAL_UART_LOOPBACK_TEST` 是 CMake 编译开关，默认 `OFF`。仅在 B 测试镜像上用
`bash firmware/idf.sh -DCAN_DUAL_UART_LOOPBACK_TEST=ON build` 开启。B 在 UART 模式下将
通过认证、去重的无线字节直接接纳到原无线发送队列，不进入物理 UART 输出队列；
队列满时不 ACK，沿用原来的重试、去重和过期处理。A 角色、CAN 模式及正式默认构建保持原行为。
回环接纳的字节不计入 B 的物理 UART RX/TX；无线 UART 丢弃仍按原口径累计。

`scripts/dual-uart-measure.py` 默认只打印计划；`--self-test` 仅离线检查解析与统计。
用户完成配对、两端选择 UART 且波特率一致后，显式 `--run` 才会打开 CH340 发负载。
它使用带序号、单调时钟时间戳和 CRC 的 64 字节记录，依次测 1/4/8 KiB/s 和当前 UART
波特率下的饱和发送，各 60 秒；排空后记录 RTT p50/p99/max、缺失、重复与乱序。
最大档报告该波特率下的实收持续速率，不代表跨所有波特率搜索出的无损极限。
损坏或残缺记录存在时，同时报告未验证字节及丢失上下界，不把残缺记录当成全部物理丢失。

每档前后必须读取两端 UART 累计丢弃值：可提供 `--counter-reader` 的只读 JTAG 快照脚本
（输出含 A/B 字典的 JSON），或用 `--manual-counters` 从两台 UART 总览屏幕分别录入。
JTAG 计数只在负载外暂停/恢复 CPU 读取，不修改 USB 会话协议，也不切换通信模式。
本仓库的主机测试覆盖正式构建及回环构建，包括 ACK 丢失去重、回环队列满后的拒收和恢复。

已用实际 UART worker 的主机驱动桩验证二进制收发、GPIO 路由、FIFO 完成确认、错误/溢出、切换与断线清理；用实际 WebView 页面加模拟原生通信验证分段、HEX/UTF-8、应答顺序和模式互斥。固件 1.24.2 已烧录 ESP32-S3，并以原生 USB 与外接 USB 转串口验证 115200/230400 的 HEX、UTF-8 双向字节比对及 type19/20/21。实际蓝牙/Wi-Fi 串口吞吐、外部单片机应用应答和更高波特率持续负载不由这些证据覆盖；详细通过项与限制以交付测试日志、结果文件为准。
